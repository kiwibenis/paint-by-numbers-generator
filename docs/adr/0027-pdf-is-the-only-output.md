# ADR-0027 - PDF Is the Only Output

## Status

Accepted

## Context

The generator produces printable paint-by-numbers documents.

The internal document model describes vector outlines, labels and palette
references independently from a concrete serialization format.

The project currently requires one supported generated artifact rather than
multiple parallel export formats. Each additional output format would add a
separate serialization surface, testing obligation and public integration
contract.

PDF directly supports the project's printable-document requirements and is the
format exposed by the Application and command-line interfaces.

Values originating from project data or configured palettes can reach the
generated document. Output serialization must therefore preserve document
structure regardless of those values.

## Decision

The generated artifact supported by the project shall be PDF.

Normal generation shall not expose SVG or another alternative document format.

The format-independent document representation shall be named
`VectorDocument`.

`VectorDocument` belongs to the project domain and shall not expose
PDF-library types or otherwise encode assumptions about the concrete PDF
implementation.

PDF serialization shall remain an Infrastructure responsibility behind the
Application export boundary in accordance with ADR-0003 and ADR-0008.

Values written into the PDF shall be serialized so that their contents cannot
alter the structure of the generated document.

The PDF exporter shall preserve the deterministic document semantics defined
by the Core. Library-specific metadata that is inherently generated by the PDF
implementation does not become Core state.

Serving, storing, rendering, expiring or deleting the generated PDF is outside
the generator and remains the responsibility of the integrating application.

Introducing another generated output format requires an architectural decision
that defines its purpose, integration boundary, serialization requirements and
security implications.

## Consequences

The project has one supported generated document format and one output
serialization surface to maintain.

Application and command-line integrations can rely on PDF as the generated
artifact without negotiating an output format.

The Core remains independent from PDF implementation details because it works
with `VectorDocument` rather than serializer-specific objects.

PDF-specific dependencies and serialization behavior remain confined to
Infrastructure.

Output-structure safety must be verified on the PDF exporter because it is the
boundary through which document content leaves the project.

Adding SVG or another export format is possible in the future, but it is a new
architectural capability rather than a dormant feature that can be enabled
without review.
